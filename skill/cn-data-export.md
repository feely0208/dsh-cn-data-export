# 数据出境检查

查代码与配置里的**境外数据出口**：境外端点、个人信息外发、缺安全评估说明。

## 一、法定依据

> **《数据出境安全评估办法》第二条**：向境外提供在境内运营中收集和产生的重要数据和个人信息，应申报数据出境安全评估。
> **《个人信息保护法》第三十八条、第三十九条**：向境外提供个人信息应满足特定条件，并取得**单独同意**。

**数据出境有三条合规路径**：安全评估（申报）/ 标准合同（备案）/ 认证。

## 二、它查什么

| 级别 | 项 | 性质 |
|---|---|---|
| 🟠 高 | 个人信息字段**直接发往境外端点** | 组合判据（同文件出现两者）|
| 🟠 高 | 境外服务的密钥**硬编码**在仓库里 | 客观事实 |
| 🟡 中 | 代码/配置里**出现境外服务端点** | 客观事实 · **需人工确认** |
| 🟢 低 | 文档里找不到数据出境说明 | 弱信号（absence）|

## 三、重要的边界：出现 ≠ 违规

**`EXPORT-OVERSEAS-ENDPOINT` 报的是「这里有个境外域名」，不是「你违规了」。**

```
拉取公开文档 → 从境外 CDN 取图 → 没问题
把用户手机号 POST 到境外分析服务 → 构成数据出境，需要走合规路径
```

**同一个域名，两种性质。** 所以这条规则是**提示你逐个确认**，不是判定。

真正说明问题的是 `EXPORT-PII-OVERSEAS`（个人信息 + 境外端点在同一个文件里）。

## 四、怎么用

```bash
<cli 路径> --demo
<cli 路径> --list-rules
<cli 路径> --html r.html
```

## 五、边界

- **域名清单是有限的**：覆盖常见境外 SaaS / 云服务（AWS、Google、Sentry、OpenAI…）。
  自建境外机房、IP 直连、或清单外的服务**扫不到**。
- **不做数据流分析**：不追踪变量从哪来、到哪去。只看代码里**字面出现**的域名与字段名。
- **判断不了「是否构成出境」**：法律判断需要知道数据种类、数量、接收方，那是人工的事。
- **个人信息靠字段名识别**（`phone` / `email` / `idcard`…）：命名不一致会漏。
- 与 `dsh-data-scan` 分工：那个查**境内**数据在哪（身份证/银行卡/手机号），这个查**数据去哪了**。
